# 回收站边界提示汇总修复

## 问题与策略

现成快照的只读分类统计表明，回收站路径下有 1,076 条 `reparse_point` 和 4 条 `PermissionError`。大量提示主要来自逐条记录链接跳过，不能据此判断回收站损坏。未重新遍历真实回收站，也未改写旧快照或修改系统权限。

用户确认保留可读内容的占用，合并重复提示。新策略只处理 Windows 卷根 `$RECYCLE.BIN`（大小写不敏感）中的 `reparse_point`、`PermissionError`，按回收站和类型分别汇总。普通同名目录与其他错误类型保留原有记录方式。

## 行为与边界

- 扫描卷根、回收站本身或其中的子目录都适用；不会扩大原扫描范围。
- 可读文件的逻辑大小继续计入；链接目标仍不跟随，拒绝访问仍不提权。
- 汇总记录在遍历结束或取消收尾时写入，正文保留实际发生次数；运行期间的错误数尚不包含未落库的汇总。
- 目录的不完整标记与部分快照状态保留，未知内容不表示零占用。取消任务仍保持 cancelled。
- `error_count` 和错误分页 total 继续表示已保存的记录数；两类汇总各占一条，不等于底层发生次数。
- 内存仅保留每个回收站的两类计数，不保存全部错误路径；其他错误仍流式输出。
- 新快照 policy_version 为 2，数据库结构不变；旧版本快照不重写。重启后端并重新创建快照以应用新策略。

## 复现与验证

使用已确认的 SnapshotService 公开接口，通过操作系统文件调用边界将虚拟 Windows 卷重定向至 pytest 临时目录，不访问真实卷。构造 100 个链接元数据、4 次权限拒绝、一个可读的 3 字节文件，以及独立文件消失和回收站外权限错误。

```powershell
uv run --project backend --frozen pytest backend/tests/test_snapshots.py -k recycle -q
```

修复前，三个入口的用例均因没有汇总记录而失败。修复后，三个入口均保留 3 字节可读占用，只保存两条预期边界汇总，文件消失和回收站外错误仍各自保存。另一个用例验证临时目录中的同名文件夹不受影响，以及策略版本和提示重新打开数据库后仍保持。

完整验收入口：

```powershell
$env:SPACEANALYZER_TEST_SYMLINK = Join-Path $PWD '.cache/symlink-fixture/scan/link'
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check.ps1
```

新增回归与现有链接边界、取消、持久化、API 和前端测试共同验证。未在真实回收站或整盘上执行修复后的重复扫描，未重新运行十万文件基准；本轮不改变遍历范围或布局算法。

补充回收站扫描取消回归：在首个链接元数据处理中阻塞，发出取消再释放，确认任务为 cancelled，已遇到的链接遗漏仍以一条汇总保存。
