# M1 快照核心交付

## 状态与范围

M1 的公开接口已经用户确认，当前完成业务服务、扫描器和 SQLite 存储。HTTP 接入、交互式前端和规模测量分别在后续 M2、M3、M4 提交；本提交不将它们写成已完成。

## 公开验证接口

`SnapshotService(database)` 提供 `start_scan`、`get_scan`、`cancel_scan`、`list_snapshots`、`get_snapshot`、`list_children`、`list_errors` 和关闭服务。测试通过这些入口观察行为，不通过私有方法或直接查表验证业务结果。

扫描器流式产生元数据，不依赖 HTTP 或 SQLite；仓储批量写入、维护迁移版本和查询索引；服务协调单任务、取消与中断恢复。默认统计逻辑大小，不读取正文，不跟随链接或重解析目标。

## 本阶段验证

- 合成目录、空目录、零字节文件、中文路径及大小汇总。
- SQLite 重开和历史快照不随文件后来变化而隐式更新。
- 自身数据库排除、分页、非法输入、跨快照节点拒绝。
- 权限与消失错误记录、取消、并发拒绝、受控进程中断恢复。
- 真实 Windows junction，以及用户预先准备的 SymbolicLink 目标跳过和根路径拒绝。
- 硬链接按目录项累计；只读行为与元数据保持。

显式启用用户准备的合成符号链接集成测试时，本阶段后端 11 项测试（含既有健康检查）和前端 1 项初始化页测试通过。尚未验证 HTTP、完整 UI 或十万节点性能。

## 后续阶段

M2 从 HTTP 契约验证同一业务服务；M3 从用户交互和公开 Treemap 布局函数验证；M4 区分真实合成文件扫描、数据库查询与浏览器绘制测量。测试接口范围已经确认，不重复要求用户逐条确认实现细节。
