## 交付目标

针对一个本机目录创建扫描任务，后台只读收集元数据，保存快照并通过 Python 业务接口读取。首个闭环使用测试临时目录与合成文件，HTTP 接口在 M2 接入，界面在 M3 接入。

继续执行既有约束：逻辑大小、不读取正文、不跟随链接或其他重解析目标、记录遗漏、允许取消、保留历史快照、不操作用户真实磁盘。M1 的自动验证只使用临时目录和合成数据。

## 公开接口提案

建议以 `SnapshotService` 作为 M1 的主要公开测试接口。扫描器和 SQLite 仓储在其内部协作，测试通过同一接口启动任务、观察状态和读取结果，不通过私有方法或直接查表验证业务行为。

| 操作             | 输入                           | 可观察结果                                               |
| ---------------- | ------------------------------ | -------------------------------------------------------- |
| 创建服务         | 数据库路径                     | 初始化或迁移自身数据库，恢复历史记录；不自动扫描         |
| `start_scan`     | 本机绝对目录路径               | 返回任务 ID；非法路径拒绝，同一时刻只允许一个活动任务    |
| `get_scan`       | 任务 ID                        | 状态、起止时间、处理数量、累计字节、错误数、快照 ID      |
| `cancel_scan`    | 任务 ID                        | 幂等请求取消；通过任务查询观察最终结果                   |
| `list_snapshots` | 有界分页参数                   | 按时间排序的快照摘要                                     |
| `get_snapshot`   | 快照 ID                        | 根节点、逻辑大小口径、时间范围、完整性及汇总             |
| `list_children`  | 快照 ID、节点 ID、有界分页参数 | 节点直接子项、稳定排序、数量与大小汇总；校验节点归属     |
| `list_errors`    | 快照 ID、有界分页参数          | 无法读取或扫描期间消失等错误，说明哪些结果可能缺失       |
| 关闭服务         | 无                             | 停止接收任务并释放执行器和连接，明确未完成任务的终止状态 |

接口名和职责作为本次确认范围；具体 Python 类型、内部事件格式与 SQL 不是需要逐次确认的事项。查询结果采用有类型的记录，任务、快照及节点使用稳定 ID，不通过路径拼接实现节点导航。

### 状态与完整性

- 任务状态：`queued`、`running`、`completed`、`completed_with_errors`、`cancelled`、`failed`。
- 正常完成且无遗漏才可显示为完整；读取错误、取消或执行失败不能作为完整快照展示。
- 已写入的部分结果可以保留，但必须在快照上标记完整性和原因；取消不会删除已写入的快照。
- 进程重新启动时，将遗留的 `queued`、`running` 任务标记为中断失败；后续查询仍可定位其部分结果。
- 未知 ID、非目录节点、跨快照节点、非法分页参数通过公开接口返回明确错误，交由 M2 映射为 HTTP 响应。

## 内部职责与规模约束

- `scanner/`：元数据遍历与错误分类，不依赖 FastAPI、SQLite 或模型服务。迭代遍历，检查取消信号，流式产生节点与目录汇总，不在内存中构建完整文件树。
- `storage/`：版本化迁移、批量写入、事务和有界查询。建立快照及父节点索引；写入失败回滚当前批次并记录任务失败，保留已提交结果的“不完整”标记。
- `services/`：单扫描任务协调、后台执行、快照查询与服务生命周期。任务执行与查询使用明确的连接边界，避免跨线程共享游标。
- `main.py` 在 M1 保持健康检查可运行；M2 再接入服务生命周期与 HTTP 路由。
- 每批写入及进度刷新有界，目录汇总避免全表反复扫描；具体批大小由 M4 的测量决定，不提前承诺性能。

## 文件系统策略

- 首期接受 Windows 本机绝对目录路径或盘符根目录；路径输入形式需校验。UNC 网络路径在首期拒绝，不将本机分析默认扩展为网络文件共享扫描。
- 扫描根及其祖先中的链接或重解析路径不能通过路径规范化悄悄跳过检查；扫描中遇到符号链接、目录联接或其他重解析目标时跳过并记录原因。
- 空目录和零字节文件保留。硬链接按目录项的逻辑大小累计，明确可能重复计数。
- 自动排除应用数据库及其 WAL、SHM、journal 文件，记录排除策略；不向被分析目录写入缓存、标记或日志。
- 扫描过程中目录可能变化，结果只是起止时间内的观察值，不宣称原子快照。对可观察到的消失、无法读取等错误显式记录。
- 长路径、权限和重解析点需分别有 Windows 验证记录；不能创建某种系统测试对象时，报告该测试未覆盖，不静默视为通过。

## M1 验收场景

所有场景从上述公开业务接口验证：

1. 已知大小的合成文件与嵌套空目录：根汇总、目录汇总、零字节节点和数量正确。
2. 中文及空格路径：查询能准确返回名称和父子关系。
3. 权限错误与扫描期间文件消失：保留可读结果并记录错误，完整性为部分完成。
4. 符号链接和目录联接：不遍历目标，不产生越界节点或循环；测试对象仅指向临时目录。
5. 数据库落在扫描根下：自身数据库与辅助文件不计入结果。
6. 重复启动：第二个活动任务被拒绝；取消可观察且完成后的查询稳定。
7. 重新打开同一数据库：历史快照可读；被扫描的测试文件后来变化不隐式更新旧快照。
8. 进程中断：通过受控测试子进程模拟，重新打开服务后任务可识别为中断失败。
9. 非法路径、未知 ID、跨快照节点与非法分页：公开接口明确拒绝。
10. 只读约束：对测试文件核对大小、修改时间等元数据，并观察文件系统调用；扫描逻辑没有正文读取、写入、删除、移动或改权限行为。不将系统访问时间变化解释为应用写入。

错误注入仅限文件系统、时间等系统边界，不 mock 自己的业务类或私有方法。真实操作系统权限/链接验证与边界注入分别记录，不能以模拟测试替代真实平台证据。

## 该测试接口能发现什么

M1 的业务接口测试覆盖扫描、存储、任务状态和重启后的行为，允许内部模块重构。它不覆盖 HTTP 参数与序列化、浏览器交互、Canvas 绘制和真实十万节点性能；这些分别由后续阶段验证。
